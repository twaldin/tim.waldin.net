[![Claude Code explains easl on the board: three lanes of code tiles with labelled arrows, a summary note and easl.sh in a browser tile](/blog/2026-10-04-easl/explain.jpg)](/blog/2026-10-04-easl/explain.mp4)

On Friday Andrej Karpathy posted about something I’ve been thinking about a lot while using coding agents: as the models do more of the work, more of our own work moves toward understanding what they did.

“We’ll be spending a lot more time trying to understand the outputs of language models.”

His suggestions move up the same ladder I’ve found myself climbing: ask for cleaner prose, then diagrams, then web pages (“Ask for output ‘in HTML’”), then explainer videos. His conclusion is that more of our work will “rise up the abstractions into oversight and understanding.”

I think that’s right. For a long time now, I have been asking agents for diagrams and little HTML pages constantly. They’re often much better than another few paragraphs of explanation.

The problem is that the interfaces we use still treat them like tool calls/chat transcripts.

A diagram appears in the transcript and starts scrolling away. An HTML explainer opens in a browser tab. The agent might have just spent ten minutes building me a much better representation of the system than prose could give me, but there’s nowhere for that representation to become part of the conversation.

I can’t naturally point at one box and ask “why does this call this?”. I can’t put the implementation beside the diagram and ask the agent to keep them in sync. An hour later, when I need the same explanation again, I’m often back to asking for another one.

The better the artifacts get, the stranger this feels.

If diagrams, pages, code, traces and notes are going to become the things I use to understand an agent’s work, they need somewhere to live — somewhere both of us can see, change, and point at. They ARE the topic of discussion.

And this philosophy should not only apply for HTML explainers or mermaid diagrams, but everything a human+agent pair needs. Every file in the git dir with lsp code nav, browsers that the agent is using for testing, browsers I am using to check linear, and anything else.

That’s what I built easl for.

## the transcript is a log

A chat transcript, in a GUI app or in a terminal, only grows at the bottom. It records what happened, in order, and everything I care about drifts up out of view as the session goes on.

What I've understood and what I mean is state: the diagram I'll want again, the button we are fixing, the notes I wrote in a meeting that describe what that button should look like. 

I want that state on a surface that stays put, that the agent can read and add to, and that I can point at. Karpathy calls these artifacts "discardable", and most of them are. A few I want to keep, because I'll point at them again.

## easl

easl is my attempt at that surface. It's a native Mac app with one infinite board per repository. Your agents run in real terminals on the board: your own `claude`, `codex` or any CLI, logged in as you. What they make lands beside their terminal: code tiles at exact lines with your language server, call graphs it computes, a browser, notes, HTML pages they write, and full whiteboard style drawing with shapes, arrows, etc.

Then, the magic is how you can point at anything. Hold ⌃⌥⇧⌘ (I, and many of you, already rebind this to capslock, as ‘hyper’) and click a box in a diagram, a DOM element on a browser or a paragraph in a note. Whatever you point at, it gets added to your next prompt as context.

It's free and MIT: [github.com/twaldin/easl](https://github.com/twaldin/easl), and [easl.sh](https://easl.sh).

## what I use it for

Most of my day in easl is a browser tile showing my ticket board, with my active tickets, their status and their PRs, beside the agents working on them. When I want an agent on a ticket, a PR or a change, I ⌃⌥⇧⌘-click it on the board, and it goes with my next prompt.

## how it works

Each terminal is libghostty, with your Ghostty config if you have one, running in a [zmx](https://github.com/neurosnap/zmx) session, so quitting or crashing easl doesn't stop the agent. Inside a tile, `claude` and `codex` are small wrappers that easl puts first on the PATH. They run your real binary with easl's hooks and skill for that session only, and nothing goes in your global agent, shell or Ghostty config. The hooks tell easl when an agent is working, blocked on you or done, and deliver your clicks with the next prompt. Agents build on the board through the `easl` CLI, over a local socket with a JSON schema. The [docs](https://easl.sh/docs/) have the rest.

## limits, and what I don't know yet

- macOS 14 or later on Apple silicon. No Intel, Linux or Windows build.
- Code tiles are read-only. You edit in your editor, or the agent writes the file.
- Call graphs need a language server with call hierarchy. I've checked sourcekit-lsp.
- The browser is WebKit, so Playwright and other CDP tools can't attach.
- Gemini CLI 0.60 and later runs as a plain terminal, without easl's hooks. ⌃⌥⇧⌘V pastes your clicks into it.
- No account and no API key. Your agents use the login they already have. easl has no AI of its own.
- I don't know yet how big a board can get before it's as hard to search as the scrollback.

## install

```sh
curl -fsSL https://easl.sh/install | sh
brew install neurosnap/tap/zmx oven-sh/bun/bun
```

The script is short and readable at [easl.sh/install.txt](https://easl.sh/install.txt). It downloads the release zip from GitHub, checks it against a pinned SHA-256 and moves `easl.app` to `/Applications` (or `~/Applications` if that isn't writable), with no sudo. Quit easl before you run it. curl doesn't set macOS's quarantine flag, so there's no Open Anyway step. Terminals need zmx. The `easl` CLI and every agent integration need bun.

Or download `easl-0.1.0.zip` from [releases](https://github.com/twaldin/easl/releases/tag/v0.1.0) and move `easl.app` to `/Applications`. The zip is ad-hoc signed. Clear the quarantine flag with `xattr -dr com.apple.quarantine /Applications/easl.app`, or open it once and choose Open Anyway in System Settings › Privacy & Security.

Then press ⌘T and run `claude` or `codex`. Codex asks whether to trust the folder. Answer in the terminal. Bugs and ideas go in [GitHub issues](https://github.com/twaldin/easl/issues).
