I built easl, a native Mac app where Claude Code, Codex and other coding agents run in real terminals on one infinite board, next to your code, call graphs, a browser, and the HTML pages and diagrams they build. Hold ⌃⌥⇧⌘ and click any of it, and it goes with your next prompt. It's free and MIT: [github.com/twaldin/easl](https://github.com/twaldin/easl).

## why I built it

My agents change code faster than I can keep a picture of how it fits together. I'd ask how something works and get a good answer: a few paragraphs and a pile of `path:line` references. Then it scrolled away, and an hour later I asked again.

When I did understand a piece, I still had to hand it back in words: "around line 90", a pasted path, a screenshot.

So I wanted the agent's work to stay where I can see it, and to point at the piece I mean.

## how it's wired

- **terminals.** Each terminal tile is libghostty with your Ghostty config, in a zmx session. Quit easl, crash it or rebuild it, and your agents keep working. An agent that finished while easl was closed comes back done, with its answer.
- **hooks, per session.** Inside a tile, `claude` and `codex` are small wrappers that easl puts first on the PATH. They run your real binary and add easl's hooks and skill for that session only, so nothing goes in your global agent, shell or Ghostty config. The hooks tell easl when an agent is working, blocked on you or done, and deliver what you clicked with your next prompt.
- **the socket.** The hooks, the `easl` CLI (it ships inside the app), and the Python and TypeScript clients all talk to easl over one local Unix socket with a JSON schema. Agents create tiles in atomic batches and render any region offscreen without moving your view.

## what agents do with it

A code tile is the whole file, with your language server (hover, go to definition, references) and a git gutter against your branch. A call graph shows who calls a function and what it calls; a node's + opens one more level, and it recomputes when the files change. Agents drive browser tiles with `easl browser`: open, snapshot, click, type, eval, screenshot. Notes keep their code excerpts live against the files they quote, and an arrow can end on one line of code. Whatever an agent makes lands next to its terminal, and ⌘Z undoes it.

Then you point. Hold ⌃⌥⇧⌘ and click a line of code, an element on a page, a paragraph in a note or a command's output. It lands as a chip in a tray at the bottom of the window, and your next prompt in that terminal carries it. So the prompt can be "fix this".

The terminal keeps the transcript. The board keeps the work.

## limits

- macOS 14 or later, Apple silicon only.
- Call graphs need a language server with call hierarchy. I've verified sourcekit-lsp.
- The browser is WebKit, so Playwright and other CDP tools can't attach.
- easl has no account and no API key. Your agents use the login they already have.

## install

```sh
curl -fsSL https://easl.sh/install | sh
brew install neurosnap/tap/zmx oven-sh/bun/bun
```

The script is short and readable at [easl.sh/install.txt](https://easl.sh/install.txt). It downloads the release zip from GitHub, checks it against a pinned SHA-256 and moves `easl.app` to `/Applications`, with no sudo. curl doesn't set macOS's quarantine flag, so there's no Open Anyway step. Terminals need zmx; the `easl` CLI and the hooks need bun.

Or download `easl-0.1.0.zip` from [releases](https://github.com/twaldin/easl/releases/tag/v0.1.0) and move `easl.app` to `/Applications`. It's ad-hoc signed, not notarized, so open it once and choose Open Anyway in System Settings › Privacy & Security, or run `xattr -dr com.apple.quarantine /Applications/easl.app`.

Then press ⌘T and run `claude` or `codex`. Bugs and ideas go in [GitHub issues](https://github.com/twaldin/easl/issues).
