The diagram was in one window. The page was in another. The note was in a third. The agent was in a fourth, and I was typing a description of the other three.

I gave up on the description.

When I did get an answer, it was a few paragraphs and a pile of `path:line` references. Then it scrolled away, and an hour later I asked again.

When I understood a piece, I still had to hand it back as a pasted path or a screenshot.

I wanted the agent's work to stay where I can see it, and to point at the piece I mean.

easl is a native Mac app. The agent runs in a real terminal on a board, next to the code, a call graph from the language server, a browser, notes, and pages the agent writes. I hold ⌃⌥⇧⌘ and click a box in a diagram, an element on a page and an item in a note. Those three go with the next prompt. The prompt can be "fix this".

It's free and MIT: [github.com/twaldin/easl](https://github.com/twaldin/easl), and [easl.sh](https://easl.sh).

## the click

The click puts a chip in a tray at the bottom of the window. The tray names the terminal that will get it. The next prompt I submit there carries the chip.

Four keys, because the smaller chords are taken. ⌘-click opens a link. ⌃-click is the menu. Without the chord, ⇧⌘M adds what you've selected or have the cursor in. Caps Lock can send all four, with Karabiner-Elements.

A shape brings what it encloses and what it connects to. A note item brings the headings above it. A command's output brings the command and its exit code.

Claude Code and Codex take the chip with the prompt, once bun is installed. opencode and Gemini CLI before 0.60 do too, and omp after one symlink. Aider, and any CLI without hooks, needs ⌃⌥⇧⌘V. That pastes the chips. It does not press Return.

## what lands beside the terminal

A call graph is who calls a function and what it calls, computed by your language server. A node's + opens one more level. A file the graph shows changing recomputes it. A deleted function stays, with a stale badge. This needs call hierarchy. I have checked sourcekit-lsp.

A note can quote a file. The excerpt shows the code as it is now, and follows the lines if they move. If that code is gone, the excerpt says it is stale.

A browser tile is a WebKit page with easl's own profile. Claude Code, Codex and any CLI drive it with `easl browser`: open, snapshot, click, type, eval, screenshot. omp uses its own browser tool. The page's errors show on the tile.

An HTML tile is a page the agent writes, separate from the browser tile. Sandboxed, with Tailwind, Mermaid and code excerpts built in.

What an agent creates lands next to its terminal. The title bar names that terminal. The view does not move. With the board focused, ⌘Z undoes it and names what it undid.

One board per repository. Every worktree and branch opens it.

## how a terminal is wired

Each terminal is libghostty. You don't need the Ghostty app. If you have a Ghostty config, the tile uses its theme, font family and keybinds.

The session is [zmx](https://github.com/neurosnap/zmx), installed separately. Quit easl, crash it, rebuild it, or close the board's tab, and the agent keeps running. Reopen the folder and the tile is back. If it finished while easl was closed, it comes back done, with its answer. After a reboot, Claude Code, Codex and omp relaunch their recorded sessions.

Inside a tile, `claude` and `codex` are small wrappers that easl puts first on the PATH. They run your real binary and add easl's hooks and skill for that session only, so nothing goes in your global agent, shell or Ghostty config. The hooks tell easl when an agent is working, blocked on you or done, and deliver what you clicked with your next prompt. Without bun on PATH, the hook does nothing.

The hooks, the `easl` CLI (it ships inside the app), and the Python and TypeScript clients talk to easl over a local Unix socket, with a JSON schema.

## limits

- macOS 14 or later, Apple silicon only. No Intel, Linux or Windows build.
- Code tiles show the file, with hover, go to definition and references. You edit in your editor, or the agent writes the file.
- Call graphs need a language server with call hierarchy. Checked: sourcekit-lsp.
- The browser is WebKit. Playwright and other CDP tools can't attach.
- Gemini CLI 0.60 and later runs as a plain terminal, without easl's hooks. ⌃⌥⇧⌘V pastes your clicks into it.
- No account and no API key. Your agents use the login they already have. easl has no AI of its own.

## install

```sh
curl -fsSL https://easl.sh/install | sh
brew install neurosnap/tap/zmx oven-sh/bun/bun
```

The script is short and readable at [easl.sh/install.txt](https://easl.sh/install.txt). It downloads the release zip from GitHub, checks it against a pinned SHA-256 and moves `easl.app` to `/Applications` (or `~/Applications` if that isn't writable), with no sudo. Quit easl before you run it. curl doesn't set macOS's quarantine flag, so there's no Open Anyway step. Terminals need zmx. The `easl` CLI and every agent integration need bun.

Or download `easl-0.1.0.zip` from [releases](https://github.com/twaldin/easl/releases/tag/v0.1.0) and move `easl.app` to `/Applications`. The zip is ad-hoc signed. Clear the quarantine flag with `xattr -dr com.apple.quarantine /Applications/easl.app`, or open it once and choose Open Anyway in System Settings › Privacy & Security.

Then press ⌘T and run `claude` or `codex`. Codex asks whether to trust the folder. Answer in the terminal. Bugs and ideas go in [GitHub issues](https://github.com/twaldin/easl/issues).
