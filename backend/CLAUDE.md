# backend/

Node.js 24 (`node:24-alpine`) + Express 5 + Socket.IO 4 server. `server.js` is socket wiring, HTTP routes and audit logging; session policy is split into three modules — `SessionManager` (`session.js`, per-connection behaviour) → `Admission` (`admission.js`, who gets a slot) → `SessionLifecycle` (`lifecycle.js`, every dockerode call plus the warm pool) — and every container spec comes from `sandbox-policy.js`. In compose the backend reaches Docker only through `tecnativa/docker-socket-proxy` (`DOCKER_HOST=tcp://socket-proxy:2375`, `docker-compose.yml`); never hand it a raw `/var/run/docker.sock`. Without `DOCKER_HOST`, `DockerodeAdapter` falls back to dockerode's local-socket default — local development only.

## Runtime model: warm pool, one lease per IP

`SessionManager.handleConnect` → `Admission.tryAcquire(ip, { persistentId, initCommand, onOutput, onClose })` → `SessionLifecycle.lease` or `rebind`. `tryAcquire` resolves `{ mode: 'cold' | 'resume', lease }` or `{ mode: 'denied', reason }`; if it throws, the client gets `error` `'Failed to create terminal session'`. Lease ids are `lease-<clock>-<n>`, `handleId` is the container id, and `lease.state` moves `pending` → `active` → `zombie` → `ended`.

- **Pool**: `SessionLifecycle` (`poolSize` 5, passed by `SessionManager`) keeps containers created, started, pre-resized and attached (`_createPrepared`, label `session=pool`). `_warmOne` only buffers what the container prints while warming (the zsh prompt); `lease` replays that buffer through the new sink. Nothing runs `welcome` during warm-up. `_fillPool` refills after every lease and whenever a pooled stream closes; a failed warm releases its slot and waits for the next trigger instead of looping.
- **Capacity**: `tryAcquire` checks `_capacityUsed()` and adds to `reservations` synchronously, before any `await`, so concurrent connects can never overshoot `maxSessions` (40). Full → `reason: 'full'` → client `error` `'Server is at capacity. Please try again shortly.'`. `_capacityUsed()` = `reservations.size + lifecycle.capacityUsed()` (live handles + pooled containers): an active lease is counted in both terms and the pool counts too, so until TWA-52 lands the real visitor limit is far below 40 (the 19th visitor is rejected with production settings).
- **One live lease per IP**: `ipLeases: Map<ip, leaseId>`. A new connection from an IP with a live lease and no matching `sessionId` destroys the old lease first (`Admission.destroy` → `SessionLifecycle.destroy` unbinds the stream, then `stream.end()` + kill/remove), transfers its reservation, then leases a fresh container. The evicted socket receives no message; its conn lingers on the dead stream until its timers fire or it disconnects.
- **Persistent restore**: handshake `auth.sessionId` (the UUID the frontend persists per browser; see `frontend/CLAUDE.md`) is stored as `lease.persistentId`. `_findPersistentLease` scans active then zombie leases. Same IP → `_restore`: a zombie is reactivated, then `SessionLifecycle.rebind` swaps the stream listeners to the new socket → `mode: 'resume'`. Different IP → `reason: 'ip-mismatch'`. Every non-`full` denial (`ip-mismatch`, `eviction-failed`, `lease-failed`, `cancelled`, `rebind-failed`, `not-found`) shows `'Session unavailable. Please refresh.'`.
- **Zombies**: `handleDisconnect` → `Admission.zombify(leaseId)`: the lease leaves `activeLeases` / `ipLeases`, releases its reservation, and waits in `zombieLeases: Map<leaseId, { lease, timer }>` for `ZOMBIE_GRACE_MS` (30 s); an older zombie from the same IP is destroyed. Only a reconnect presenting the same `sessionId` from the same IP revives it — a same-IP reconnect without one leases a fresh container. Expiry → `Admission.destroy`.

## Timers and limits

| Timer                                                    | Field                          | Reset on                                                              | Action |
|----------------------------------------------------------|--------------------------------|-----------------------------------------------------------------------|--------|
| `sessionTimeout` (5 min)                                 | `state.timeout`                | every accepted `handleInput`                                          | `_destroy`, emit `output` `[session idle — closed]`, disconnect |
| `noInputTimeout` (60 s) / `noInputTimeoutVisible` (5 min) | `state.noInputTimer`          | first `handleInput` cancels it for good; a visibility flip re-arms it | `_destroy` + disconnect if no keystroke ever arrived |
| `resizeFallback` (6 s)                                   | `state.resizeFallback`         | —                                                                     | set `firstResizeApplied` so the initCommand gate opens |
| Connection rate limit                                    | `Admission.connectionTracker`  | rolling `RATE_LIMIT_WINDOW_MS` (60 s)                                 | `checkConnectionRate` is false after `MAX_CONNECTIONS_PER_IP` (30) → `error` `'Too many connections. Please wait a minute.'` |

The client emits `visibility` `{ hidden }` on connect and on every `visibilitychange`; `pageVisible === true` selects the 5 min window, while hidden pages and clients that never report (bots without JS) keep 60 s. `resize` / `visibility` that arrive before `tryAcquire` resolves are parked in `pendingResize` / `pendingHidden` and replayed. Resize and visibility never reset `sessionTimeout`. `handleInput` drops non-string or > 1024-char payloads; `handleResize` clamps to 10–500 cols × 2–200 rows. A 404 from Docker on resize (container gone) calls `_destroy`: conn and lease are torn down silently — nothing is emitted and the socket is not disconnected.

## Container spec (`sandbox-policy.js`)

`SANDBOX_POLICY` is frozen data; `buildContainerSpec(sessionId)` is the only builder and `SessionLifecycle._createPrepared` its only runtime caller (tests call it directly to assert the spec). Image `twaldin/terminal-portfolio:latest`, hostname `twaldin`, user `portfolio`, workdir `/home/portfolio`, labels `app=terminal-portfolio` + `session=<leaseId|pool>`, `NetworkMode: none`, `CapDrop: ALL` + `CapAdd: SETUID, SETGID` (the `sudo` demo), `Memory` 512 MB, `CpuQuota` 50000 (0.5 CPU), `PidsLimit` 100, `ReadonlyRootfs: false`, `Tmpfs /tmp` `rw,noexec,nosuid,size=100m`. `Env`: `TERM=xterm-256color`, `PS1=tim.waldin.net:$ `, `LANG=C.UTF-8`, `LC_ALL=C.UTF-8` (multi-byte glyphs in `less` / `cat`).

`COLUMNS` / `LINES` are deliberately absent from `Env`: scripts that read them at startup would render at 80×24 until the first client resize lands, so the initCommand is gated on both `promptSeen` and `firstResizeApplied` (`_maybeRunInitCommand`) and figlet/nvim/blog never render at the wrong size.

## Boot sequence for a new visitor

1. Socket connects with `auth.sessionId` (persistent UUID) and `auth.initCommand` (URL-derived; `''` is allowed). IP = `x-real-ip` header (set by nginx) or the socket address. `server.js` logs `session_start` and calls `SessionManager.handleConnect`.
2. `Admission.checkConnectionRate(ip)` fails → `error` + disconnect.
3. `Admission.tryAcquire` decides `resume` vs `cold` (Runtime model above). A cold lease takes a warm container (`_takeFromPool`) or builds one (`_createPrepared`: create → start → resize 140×40 → attach), then `bindStream`s the sink, replays the buffered prompt and refills the pool.
4. `socket.emit('session_status', { mode })`; parked resize / visibility are applied. On `resume` the gate is re-armed (`promptSeen = true`, `firstResizeApplied = false`) and `\x03` is written so a script left running by the previous socket stops; the first applied resize then triggers the initCommand.
5. `_maybeRunInitCommand` runs once `promptSeen` (output containing `~ `) and `firstResizeApplied` are both true; `resizeFallback` opens the gate at the pre-resize size if no resize ever arrives.
6. `_maybeRunInitCommand` picks the command: `''` is a no-op sentinel (blog cold pages already show content), otherwise `initCommand || 'boot'`. `_autoType` types only a literal `welcome` char-by-char (20 ms/char, `tti` events `welcome-start` / `welcome-enter-sent`); everything else is written atomically with `\r`. The initCommand replays on every connect, including refresh/resume.

## InitCommand validation

`_autoType` re-checks `/^[a-z0-9 ._/+=:,@-]+$/i` and length ≤ 200; a failure logs a warning and falls back to `boot`. This blocks shell metacharacters and over-long strings only — the route allowlist lives in the frontend (`pathToCommand` in `frontend/src/lib/websocket.ts`).

## Orphan reclaim and maintenance

`SessionLifecycle.reclaimOrphans` lists containers matching `labelFilter()` (`app=terminal-portfolio`), skips ids held in `handles` or `pool`, and kill+removes the rest; it never calls a Docker prune endpoint, and nothing removes images. It runs once when `SessionManager` is constructed with a real lifecycle (tests inject fakes and skip it) and every 60 s from `startPoolMaintenance`, which also runs `Admission.pruneStaleRateLimits`.

## Tests

`npm test` = `node --test test/*.test.js proxy-validator/test/*.test.js`. No Docker needed. `node --test` runs the node:test suites natively and executes the plain scripts once each, failing on a non-zero exit (they set `process.exitCode = 1`).

- `test/admission.test.js` — node:test; fake lifecycle + fake clock: capacity atomicity under a 60-connect burst, `ip-mismatch`, eviction before the replacement lease, a failed lease releases its reservation, 30 s zombie expiry, restore rebinds to the new sink, 30/min rate limit.
- `test/lifecycle.test.js` — plain script over `test/lifecycle-fake.js` (`LifecycleFake`, an in-memory stand-in for `DockerodeAdapter`): policy spec, label-scoped reclaim, pool refill, failed-warm slot release, alt-screen replay, split-preamble filter, write/resize/close/destroy delegation.
- `test/session-controller.test.js` — `SessionManager` over fake admission + lifecycle: `session_status` cold/resume, input/resize forwarding, synchronous `zombify`, rate-limit denial, idempotent `startPoolMaintenance`.
- `test/no-input-visibility.test.js` — the visibility-aware no-input timer with scaled-down windows (60 ms / 300 ms).
- `test/admin-auth.test.js`, `test/logger-rotation.test.js`, `test/pageviews.test.js` — `safeEqual` + `basicAuth`; single-backup rotation + `readAll` order; `/pv` validation, rate limit, overflow bucket and rollup.
- `proxy-validator/test/validate.test.js` — node:test; `assertSandboxCompliant` rejections plus the live proxy's path allowlist against a stub upstream.

## Things to watch

- `_handleStreamClose` only fires for a live conn (it emits `[session ended — refresh for a new terminal]` + `session_end`, and the frontend drops its `sessionId`). A zombie's stream close reaches the `onClose` wrapper from `Admission._callbacksFor`, which destroys the lease — a container that dies after zombification is freed immediately, not at the 30 s expiry.
- `Admission.zombify` is synchronous and returns a boolean; do not `.catch()` it (`session-controller.test.js` guards this).
- `SessionLifecycle.bindStream` is the only stream-forwarding wiring point: `rebind` replaces both listeners instead of stacking, and when `handle.inAltScreen` it replays `ALT_SCREEN_REPLAY` (`\x1b[?1049h\x1b[2J\x1b[H`) so nvim/htop redraw into the right xterm.js buffer. `_trackAltScreen` follows `\x1b[?1049h/l` and `\x1b[?47h/l` across chunk boundaries (`escapeTail`). `_withoutAttachPreamble` strips the hijacked stream's `{"stream":true,…}` header even when it arrives split.
- A second tab presenting the same `sessionId` from the same IP takes over the stream via `rebind`, but the first tab's conn still references the lease: its disconnect zombifies (and 30 s later destroys) the shared shell, and its idle timer can destroy it too. Tracked as TWA-53.
- `DockerodeAdapter` forces `protocol: 'http'`; docker-modem would otherwise auto-negotiate TLS on port 2376, the proxy-validator's port. `SessionLifecycle` calls only container create/start/attach/resize/kill/remove/list on the adapter (its other methods are unused) — don't add `EXEC=1` to the socket-proxy env; nothing needs it, and it would expose `docker exec` to a compromised backend.
- `proxy-validator/` is not in the data path: its HTTP forward cannot relay dockerode's hijacked `attach` stream (`docker-compose.yml` comment). `validate.js` checks image, `NetworkMode`, `Privileged`, `Binds` / `Mounts` / `Devices`, host namespace fields, `CapAdd` / `CapDrop`, `SecurityOpt` and the three resource limits against `SANDBOX_POLICY`; it does not check `User` or `Tmpfs`.
