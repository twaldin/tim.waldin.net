# backend/

Node.js 24 (`node:24-alpine`) + Express 5 + Socket.IO 4 server. `server.js` is socket wiring, HTTP routes and audit logging; session policy is split into three modules — `SessionManager` (`session.js`, per-connection behaviour) → `Admission` (`admission.js`, who gets a slot) → `SessionLifecycle` (`lifecycle.js`, every dockerode call plus the warm pool) — and every container spec comes from `sandbox-policy.js`. Docker is reached only through `tecnativa/docker-socket-proxy` at `DOCKER_HOST=tcp://socket-proxy:2375` (`docker-compose.yml`), never a raw `/var/run/docker.sock`.

## Files

- **`server.js`** — Express app + Socket.IO server, CORS allowlist (`PROD_ORIGINS` when `NODE_ENV=production`, else `DEV_ORIGINS`), per-socket command buffer that turns raw keystrokes into `command` audit events, `/health` and `/stats` (`activeSessions` and `totalContainers` are both `SessionManager.conns.size`), `POST /pv`, `/admin`, `startPoolMaintenance()`, graceful shutdown on SIGINT/SIGTERM (`pageviews.flushRollup()` → `destroyAllSessions()` → `server.close`, 5 s force exit).
- **`session.js`** — `SessionManager`. Per-connection controller: rate-limit gate, `session_status` emit, idle / no-input timers, resize clamp + initCommand gate, initCommand validation and auto-typing, stream-close handling. Holds no dockerode and does no capacity bookkeeping.
- **`admission.js`** — `Admission`. Atomic capacity reservation (`maxSessions` 40), one live lease per IP (`ipLeases`), persistent-session restore, 30 s zombie grace, connection rate limit. Lease ids are `lease-<clock>-<n>`; `handleId` is the container id; `lease.state` moves `pending` → `active` → `zombie` → `ended`.
- **`lifecycle.js`** — `SessionLifecycle` + `DockerodeAdapter`. Warm pool, `lease` / `rebind` / `write` / `resize` / `destroy`, attach-preamble filter, alt-screen tracking, label-scoped `reclaimOrphans`.
- **`sandbox-policy.js`** — `SANDBOX_POLICY`, `buildContainerSpec(sessionId)`, `labelFilter()`. Dependency-free so `proxy-validator/` can import it too; the only place the container spec is built.
- **`admin.js`** — basic-auth `/admin` router (`ADMIN_EMAIL`, default `timothy@waldin.net`; `ADMIN_PASSWORD`, 503 if unset). Sessions grouped by IP plus a pageview table, `/admin/api/sessions`, `/admin/api/pageviews`. HMAC-normalised constant-time compare; 5 bad passwords within 10 min → 10 min per-IP lockout (429 + `Retry-After`); a missing header is a 401 that does not count.
- **`logger.js`** — JSONL audit log (`LOG_FILE`, default `data/events.jsonl`, i.e. `/app/data` on the `backend_data` volume). Events `session_start`, `command`, `session_end`, `pageview_rollup`, each stamped `at`. Single-backup rotation at `LOG_MAX_BYTES` (5 MB) → `events.jsonl.1`; `readAll()` reads both files.
- **`pageviews.js`** — `POST /pv` beacon (`{ path }` sent as text/plain): `PATH_RE`, ≤ 200 chars, 30/min per IP → 429, at most `PV_MAX_PATHS` (1000) distinct paths then `(other)`; in-memory totals plus a UTC-daily `pageview_rollup` audit event on rollover and shutdown.
- **`theme.js`** — generated by `scripts/generate-themes-lib.py`; the admin page's accent colour.
- **`proxy-validator/`** — body-validating Docker proxy (`index.js` allowlists paths, `validate.js` rejects any create request looser than `SANDBOX_POLICY`; own `Dockerfile`). Parked: not in `docker-compose.yml` because its HTTP forward cannot relay dockerode's hijacked `attach` stream. Its tests run under `npm test`.
- **`test/`** — see Tests. **`Dockerfile`** builds from the repo root (`context: .`), so **`Dockerfile.dockerignore`** — not `.dockerignore` — keeps `test/`, `proxy-validator/test/`, `node_modules`, `.env*` and logs out of the image. **`package.json`**: `npm start` → `node server.js`; `npm test` → `node --test test/*.test.js proxy-validator/test/*.test.js`.

## Runtime model: warm pool, one lease per IP

`SessionManager.handleConnect` → `Admission.tryAcquire(ip, { persistentId, initCommand, onOutput, onClose })` → `SessionLifecycle.lease` or `rebind`. `tryAcquire` resolves `{ mode: 'cold' | 'resume', lease }` or `{ mode: 'denied', reason }`.

- **Pool**: `SessionLifecycle` (`poolSize` 5, passed by `SessionManager`) keeps containers created, started, pre-resized to 140×40 and attached (`_createPrepared`, label `session=pool`). `_warmOne` only buffers what the container prints while warming (the zsh prompt); `lease` replays that buffer through the new sink. Nothing runs `welcome` during warm-up. `_fillPool` refills after every lease and whenever a pooled stream closes; a failed warm releases its slot and waits for the next trigger instead of looping.
- **Capacity**: `tryAcquire` checks `_capacityUsed()` and adds to `reservations` synchronously, before any `await`, so concurrent connects can never overshoot `maxSessions` (`admission.test.js` drives 60 at once against a fake lifecycle and gets exactly 40). Full → `reason: 'full'` → client `error` `'Server is at capacity. Please try again shortly.'`. `_capacityUsed()` = `reservations.size + lifecycle.capacityUsed()` (live handles + pooled containers): an active lease is counted in both terms and the pool counts too, so the real visitor limit is far below 40 (TWA-52: the 19th visitor is rejected with production settings).
- **One live lease per IP**: `ipLeases: Map<ip, leaseId>`. A new connection from an IP with a live lease and no matching `sessionId` destroys the old lease first (`Admission.destroy` → `SessionLifecycle.destroy` unbinds the stream, then `stream.end()` + kill/remove), transfers its reservation, then leases a fresh container. The evicted socket receives no message; its conn lingers on the dead stream until its timers fire or it disconnects.
- **Persistent restore**: handshake `auth.sessionId` (a UUID the frontend keeps in `localStorage` as `terminal-session-id`) is stored as `lease.persistentId`. `_findPersistentLease` scans active then zombie leases. Same IP → `_restore`: a zombie is reactivated, then `SessionLifecycle.rebind` swaps the stream listeners to the new socket → `mode: 'resume'`. Different IP → `reason: 'ip-mismatch'`. Every non-`full` denial (`ip-mismatch`, `eviction-failed`, `lease-failed`, `cancelled`, `rebind-failed`, `not-found`) shows `'Session unavailable. Please refresh.'`.
- **Zombies**: `handleDisconnect` → `Admission.zombify(leaseId)` (synchronous, returns a boolean): the lease leaves `activeLeases` / `ipLeases`, releases its reservation, and waits in `zombieLeases: Map<leaseId, { lease, timer }>` for `ZOMBIE_GRACE_MS` (30 s); an older zombie from the same IP is destroyed. Only a reconnect presenting the same `sessionId` from the same IP revives it — a same-IP reconnect without one leases a fresh container. Expiry → `Admission.destroy`.

## Idle / bot timers (`SessionManager`)

| Timer                                                    | Field                          | Reset on                                                              | Action |
|----------------------------------------------------------|--------------------------------|-----------------------------------------------------------------------|--------|
| `sessionTimeout` (5 min)                                 | `state.timeout`                | every `handleInput`                                                   | `_destroy`, emit `output` `[session idle — closed]`, disconnect |
| `noInputTimeout` (60 s) / `noInputTimeoutVisible` (5 min) | `state.noInputTimer`          | first `handleInput` cancels it for good; a visibility flip re-arms it | `_destroy` + disconnect if no keystroke ever arrived |
| `resizeFallback` (6 s)                                   | `state.resizeFallback`         | —                                                                     | set `firstResizeApplied` so the initCommand gate opens |
| Connection rate limit                                    | `Admission.connectionTracker`  | rolling `RATE_LIMIT_WINDOW_MS` (60 s)                                 | `checkConnectionRate` is false after `MAX_CONNECTIONS_PER_IP` (30) → `error` `'Too many connections. Please wait a minute.'` |

The client emits `visibility` `{ hidden }` on connect and on every `visibilitychange`; `pageVisible === true` selects the 5 min window, while hidden pages and clients that never report (bots without JS) keep 60 s. `resize` / `visibility` that arrive before `tryAcquire` resolves are parked in `pendingResize` / `pendingHidden` and replayed. Resize and visibility never reset `sessionTimeout`. `handleInput` drops non-string or > 1024-char payloads; `handleResize` clamps to 10–500 cols × 2–200 rows, and a 404 from Docker destroys the session so the client reconnects fresh.

## Container spec (`sandbox-policy.js`)

`SANDBOX_POLICY` is frozen data and `buildContainerSpec(sessionId)` the only builder; `SessionLifecycle._createPrepared` is its only caller. Image `twaldin/terminal-portfolio:latest`, hostname `twaldin`, user `portfolio`, workdir `/home/portfolio`, labels `app=terminal-portfolio` + `session=<leaseId|pool>`, `NetworkMode: none`, `CapDrop: ALL` + `CapAdd: SETUID, SETGID` (the `sudo` demo), `Memory` 512 MB, `CpuQuota` 50000 (0.5 CPU), `PidsLimit` 100, `ReadonlyRootfs: false`, `Tmpfs /tmp` `rw,noexec,nosuid,size=100m`. `Env`: `TERM=xterm-256color`, `PS1=tim.waldin.net:$ `, `LANG=C.UTF-8`, `LC_ALL=C.UTF-8` (multi-byte glyphs in `less` / `cat`).

`COLUMNS` / `LINES` are deliberately absent from `Env`: scripts that read them at startup would render at 80×24 until the first client resize lands, so the initCommand is gated on both `promptSeen` and `firstResizeApplied` (`_maybeRunInitCommand`) and figlet/nvim/blog never render at the wrong size.

## Boot sequence for a new visitor

1. Socket connects with `auth.sessionId` (persistent UUID) and `auth.initCommand` (URL-derived; `''` is allowed). IP = `x-real-ip` header (set by nginx) or the socket address. `server.js` logs `session_start` and calls `SessionManager.handleConnect`.
2. `Admission.checkConnectionRate(ip)` fails → `error` + disconnect.
3. `Admission.tryAcquire`: persistent match → `rebind` (`resume`); otherwise evict the IP's live lease, reserve a slot, `SessionLifecycle.lease` (`cold`). `lease` takes a warm container (`_takeFromPool`) or creates one (`_createPrepared`: create → start → resize 140×40 → attach), `bindStream`s the sink, replays the buffered prompt, then refills the pool.
4. `socket.emit('session_status', { mode })`; parked resize / visibility are applied. On `resume` the gate is re-armed (`promptSeen = true`, `firstResizeApplied = false`) and `\x03` is written so a script left running by the previous socket stops; the first applied resize then triggers the initCommand.
5. `_maybeRunInitCommand` runs once `promptSeen` (output containing `~ `) and `firstResizeApplied` are both true; the 6 s `resizeFallback` opens the gate at the pre-resize 140×40 size.
6. `_autoType`: default `boot`; `''` is a no-op sentinel (blog cold pages already show content). Only a literal `welcome` is typed char-by-char (20 ms/char, `tti` events `welcome-start` / `welcome-enter-sent`); everything else is written atomically with `\r`. The initCommand replays on every connect, including refresh/resume.

## InitCommand validation

`_autoType` re-checks `/^[a-z0-9 ._/+=:,@-]+$/i` and length ≤ 200; a failure logs a warning and falls back to `boot`. This only blocks shell metacharacters — the route allowlist lives in the frontend (`pathToCommand` in `frontend/src/lib/websocket.ts`).

## Orphan reclaim and maintenance

`SessionLifecycle.reclaimOrphans` lists containers matching `labelFilter()` (`app=terminal-portfolio`), skips ids held in `handles` or `pool`, and kill+removes the rest; it never calls a Docker prune endpoint, and nothing removes images. It runs once when `SessionManager` is constructed with a real lifecycle (tests inject fakes and skip it) and every 60 s from `startPoolMaintenance`, which also runs `Admission.pruneStaleRateLimits`.

## Tests

`npm test` (`node --test test/*.test.js proxy-validator/test/*.test.js`; no Docker needed; 48 tests) runs two node:test suites — `test/admission.test.js` (fake lifecycle + fake clock: 40-slot atomicity, `ip-mismatch`, eviction order, 30 s zombie expiry, rebind to the new sink, 30/min rate limit) and `proxy-validator/test/validate.test.js` — plus plain scripts executed once each under the same runner: `test/lifecycle.test.js` (uses `test/lifecycle-fake.js`, an in-memory `DockerodeAdapter`: spec, reclaim, pool refill, alt-screen replay, preamble filter), `test/session-controller.test.js` (`SessionManager` over fake admission + lifecycle), `test/no-input-visibility.test.js` (scaled-down timer windows), `test/admin-auth.test.js`, `test/logger-rotation.test.js`, `test/pageviews.test.js`. The plain scripts set `process.exitCode = 1` on failure so the runner reports them.

## Things to watch

- `_handleStreamClose` only fires for a live conn (it emits `[session ended — refresh for a new terminal]` + `session_end`, and the frontend drops its `sessionId`). A zombie's stream close reaches the `onClose` wrapper from `Admission._callbacksFor`, which destroys the lease — a container that dies after zombification is freed immediately, not at the 30 s expiry.
- `Admission.zombify` is synchronous; do not `.catch()` it (`session-controller.test.js` guards this).
- `SessionLifecycle.bindStream` is the only stream-forwarding wiring point: `rebind` replaces both listeners instead of stacking, and when `handle.inAltScreen` it replays `ALT_SCREEN_REPLAY` (`\x1b[?1049h\x1b[2J\x1b[H`) so nvim/htop redraw into the right xterm.js buffer. `_trackAltScreen` follows `\x1b[?1049h/l` and `\x1b[?47h/l` across chunk boundaries (`escapeTail`). `_withoutAttachPreamble` strips the hijacked stream's `{"stream":true,…}` header even when it arrives split.
- A second tab presenting the same `sessionId` from the same IP takes over the stream via `rebind`, but the first tab's conn still references the lease: its disconnect zombifies (and 30 s later destroys) the shared shell, and its idle timer can destroy it too (TWA-53).
- `DockerodeAdapter` forces `protocol: 'http'`; docker-modem would otherwise auto-negotiate TLS on port 2376, the proxy-validator's port. `lifecycle.js` uses only container create/start/attach/resize/kill/remove/list — don't add `EXEC=1` to the socket-proxy env; nothing needs it, and it would expose `docker exec` to a compromised backend.
